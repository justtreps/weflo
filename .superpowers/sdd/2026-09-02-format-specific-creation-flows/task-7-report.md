# Task 7 — Generated full-template previews

## Result

Implemented the generated preview pipeline for all 21 selectable templates. Each template has a deterministic desktop `1440×1100` WebP and mobile `390×844` WebP, a byte-hashed manifest entry, and a generated PNG contact sheet.

The gallery now resolves image paths from `public/template-previews/manifest.json`; its fallback markup remains in place. The enlarged dialog now exposes desktop/mobile controls and says `Exemple fictif` visibly.

## RED / GREEN

1. **RED:** `tests/template-preview.test.ts` failed because `src/create/template-preview.ts` did not exist. `tests/template-preview-assets.test.ts` failed because the manifest was absent.
2. **GREEN:** Added the isolated preview document renderer. It compiles the registered recipe, uses preview-only fictitious product/review data, and stamps rendered HTML with `data-preview-fixture="true"`.
3. **RED:** Gallery test failed because the enlarged dialog had neither an independent device switch nor the fictitious-example disclosure.
4. **GREEN:** Added dialog controls, aspect-ratio-preserving mobile presentation, and disclosure. The gallery test passed.
5. **RED:** Asset hash test failed because the manifest hash was based on render input and byte length rather than the WebP bytes.
6. **GREEN:** Manifest hashes now use the SHA-256 prefix of the actual generated WebP bytes. The asset test passed.

## Generation and determinism evidence

- `npm run previews:templates` completed with exactly **42 WebPs** plus `contact-sheet.png` and `manifest.json`.
- Consecutive final runs produced the same values:
  - Manifest SHA-256: `87DD13929FC153931C23BA073CA3D7DFF75896DEC16D1C10931EE28674BE3CDB`
  - Combined ordered WebP SHA-256: `04551DC351670E91DEFB99413D5E854F243A0E2CC52873E804A67AEBC399B149`
  - Count: `42`
- The generator fails on console errors, duplicate IDs, blank previews, and decoded images with zero natural width. It also makes lazy images eager before readiness checks.
- Remote Unsplash fixture imagery made generated bytes nondeterministic. Preview documents now map those images only inside the preview path to deterministic, locally intercepted SVG illustrations. Customer build endpoints do not import or call the preview renderer.

## Contact-sheet critique

Inspected `public/template-previews/contact-sheet.png` at desktop scale.

- All seven format groups and all three template variants are visible; no broken images or duplicated sections were observed.
- Navigation and content tiles are contained rather than cropped, so text and imagery are not clipped.
- The three templates within every format have clearly different section ordering and visual emphasis (for example, store editorial vs conversion vs maison; landing response vs editorial vs visual demo).
- The initial full-page fit made tall pages unreadable as narrow strips. The final fixed-dimension overview preserves every real rendered section as a balanced thumbnail tile. This follows the frontend-design review: one clear visual job (comparative hierarchy), restrained framing, readable structure, and no decorative chrome competing with the page preview.
